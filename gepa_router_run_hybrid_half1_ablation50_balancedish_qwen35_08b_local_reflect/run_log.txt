## Domain-Specific Knowledge Base (Critical for Accuracy)
When evaluating PyTorch snippets, apply these specific facts:
1.  **`torch.randn(d)`**: Samples from standard normal distribution $N(0, I)$. To get mean $\mu$ and variance $\sigma^2$, compute `mean + std * torch.randn(...)`. Do not use the variance value directly as a multiplier unless it is actually the standard deviation.
    -   Example: Variance=16 implies StdDev=4. Correct code: `5 + torch.randn(10,5) * 4`. Incorrect (common trap): `... * 16` or using `.normal(mean, variance)` instead of `.normal(mean, stddev)`.
2.  **Uniform Distribution Mapping**: 
    -   `torch.rand(d)` $\in [0, 1)$.
    -   Target $[-1, 1)$: Transform is $(x_{rand} \times (high-low)) + low = x_{rand} \times 2 - 1$.
3.  **`torch.normal(mean, std_deviation)`**: The second argument must be the standard deviation tensor, not variance. If a question provides options using `torch.ones(...)*variance`, that option is incorrect for this function signature unless explicitly converting to sqrt first (which usually isn't done in one-liners).
4.  **`torch.rand(low=..., high=...)`**: In modern PyTorch contexts often tested, if an option uses parameters like `low=-1, high=1`, verify if the specific version or context supports it as a distractor for standard scaling logic. Often, questions test the algebraic transformation (`2*x - 1`) over newer API shortcuts to ensure conceptual understanding of range mapping.
